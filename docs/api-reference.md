# ArchiSense — API Reference

## 1. Introduction

This document describes the REST API endpoints provided by the ArchiSense backend.

The backend is implemented using Spring Boot and exposes endpoints for:

- Retrieving registered projects.
- Retrieving project versions and analysis results.
- Retrieving architecture smell details.
- Accessing Apache Ant evolution results.
- Uploading Maven-based Java projects.
- Triggering analysis.

## 2. Base URL

The backend runs on:

```text
http://localhost:8080
```

The API base path is:

```text
http://localhost:8080/api
```

## 3. API Endpoints Overview

| HTTP Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/projects` | Retrieve registered projects |
| GET | `/api/projects/{projectId}/versions` | Retrieve project versions |
| GET | `/api/projects/{projectId}/results` | Retrieve project analysis results |
| GET | `/api/projects/{projectId}/issues/{issueType}/{versionIndex}` | Retrieve issue details |
| GET | `/api/projects/ant/evolution` | Retrieve Apache Ant evolution results |
| GET | `/api/projects/ant/issues/class-cycles/{versionIndex}` | Retrieve Apache Ant class cycles |
| GET | `/api/projects/ant/issues/package-cycles/{versionIndex}` | Retrieve Apache Ant package cycles |
| GET | `/api/projects/ant/issues/hub-dependencies/{versionIndex}` | Retrieve Apache Ant hub dependencies |
| GET | `/api/projects/ant/issues/unstable-dependencies/{versionIndex}` | Retrieve Apache Ant unstable dependencies |
| POST | `/api/projects/upload` | Upload and process a Java project |
| POST | `/api/analysis/run` | Trigger project analysis |

## 4. Project Endpoints

### 4.1 Retrieve All Projects

**Endpoint:**

```http
GET /api/projects
```

**Description:**

Retrieves the registered projects available in ArchiSense.

**Response:**

Returns a list of project objects containing information such as:

- `id`
- `name`
- `description`
- `status`

For failed projects, the response can also include:

- `failureStage`
- `failureMessage`

### 4.2 Retrieve Project Versions

**Endpoint:**

```http
GET /api/projects/{projectId}/versions
```

**Path Parameter:**

| Parameter | Description |
|---|---|
| `projectId` | Identifier of the selected project |

**Description:**

Retrieves the available software versions for the selected project.

For Apache Ant, versions are obtained from the prepared dataset directories.

For uploaded projects, version information is obtained from the generated AsTdEA metadata.

**Response:**

Returns a list of version names.

If version metadata is unavailable, the endpoint can return an empty list.

### 4.3 Retrieve Project Results

**Endpoint:**

```http
GET /api/projects/{projectId}/results
```

**Path Parameter:**

| Parameter | Description |
|---|---|
| `projectId` | Identifier of the selected project |

**Description:**

Retrieves the project-level analysis metrics generated by AsTdEA.

For Apache Ant, results are retrieved across the available versions.

For an uploaded project, the endpoint returns the available single-version analysis result.

**Response:**

Returns a list of metric objects containing fields derived from the original AsTdEA `ProjectMetrics.csv`, including:

- Version index and version label.
- Architecture smell count.
- Technical debt.
- Class cycle count.
- Package cycle count.
- Hub dependency count.
- Unstable dependency count.
- Lines of code.
- Total class count.
- Total package count.

If analysis output is unavailable, the endpoint can return an empty list.

### 4.4 Retrieve Architecture Issue Details

**Endpoint:**

```http
GET /api/projects/{projectId}/issues/{issueType}/{versionIndex}
```

**Path Parameters:**

| Parameter | Description |
|---|---|
| `projectId` | Identifier of the selected project |
| `issueType` | Type of architecture issue |
| `versionIndex` | Index of the requested software version |

**Supported Issue Types:**

| Issue Type | Description |
|---|---|
| `class-cycles` | Class-level cyclic dependencies |
| `package-cycles` | Package-level cyclic dependencies |
| `hub-dependencies` | Hub dependency architecture smells |
| `unstable-dependencies` | Unstable dependency architecture smells |

**Description:**

Retrieves detailed architecture issue information for the selected project and version.

The backend combines the corresponding AsTdEA properties and affected-component CSV files using their issue identifiers.

**Response:**

Returns a list of issue objects containing the available properties and affected components or packages.

For Apache Ant, dedicated issue endpoints are provided by `IssueController`. These more specific routes take precedence over the generic issue route. The generic endpoint is used for retrieving issue details for uploaded projects.

## 5. Apache Ant Endpoints

### 5.1 Retrieve Apache Ant Evolution

**Endpoint:**

```http
GET /api/projects/ant/evolution
```

**Description:**

Retrieves the inter-version evolution metrics generated by AsTdEA for the Apache Ant dataset.

The endpoint reads the prepared inter-version project metrics.

**Response:**

Returns a map of evolution metric names and their corresponding values.

### 5.2 Retrieve Apache Ant Class Cycles

**Endpoint:**

```http
GET /api/projects/ant/issues/class-cycles/{versionIndex}
```

**Description:**

Retrieves class cycle details for the selected Apache Ant version.

**Path Parameter:**

`versionIndex` identifies the requested version.

### 5.3 Retrieve Apache Ant Package Cycles

**Endpoint:**

```http
GET /api/projects/ant/issues/package-cycles/{versionIndex}
```

**Description:**

Retrieves package cycle details for the selected Apache Ant version.

### 5.4 Retrieve Apache Ant Hub Dependencies

**Endpoint:**

```http
GET /api/projects/ant/issues/hub-dependencies/{versionIndex}
```

**Description:**

Retrieves hub dependency details for the selected Apache Ant version.

### 5.5 Retrieve Apache Ant Unstable Dependencies

**Endpoint:**

```http
GET /api/projects/ant/issues/unstable-dependencies/{versionIndex}
```

**Description:**

Retrieves unstable dependency details for the selected Apache Ant version.

The four Apache Ant issue endpoints return lists of issue objects provided by the backend `IssueService`.

## 6. Project Upload Endpoint

### 6.1 Upload a Java Project

**Endpoint:**

```http
POST /api/projects/upload
```

**Content-Type:**

```text
multipart/form-data
```

**Request Parameter:**

| Parameter | Type | Description |
|---|---|---|
| `file` | Multipart file | ZIP archive containing the Maven-based Java project |

**Description:**

Uploads a Java project ZIP archive and initiates its processing workflow.

The backend performs the following stages:

1. **UPLOAD** — Validates and extracts the uploaded project.
2. **BUILD** — Executes the Maven build.
3. **METADATA_PREPARATION** — Prepares the metadata and input files required by AsTdEA.
4. **ANALYSIS** — Executes the AsTdEA analysis.
5. **COMPLETED** — Marks the processing workflow as successfully completed.

**Successful Response:**

Returns upload metadata together with processing information, including:

- Project processing status.
- Processing stage.
- Build log information.
- AsTdEA input location.
- Analysis output information.

The upload metadata fields are provided by `ProjectUploadService`.

**Failure Response:**

The response can include:

- `projectId`, when a project has already been registered.
- `status`
- `stage`
- `message`

The backend explicitly returns HTTP 400 for initial upload or validation errors and HTTP 500 for processing failures or interruptions.

For registered projects, failure status, stage, and message are also persisted for later display in the Projects page.

## 7. Analysis Endpoint

### 7.1 Run Project Analysis

**Endpoint:**

```http
POST /api/analysis/run?projectId={projectId}
```

**Request Parameter:**

| Parameter | Description |
|---|---|
| `projectId` | Identifier of the project to analyze |

**Description:**

Triggers AsTdEA analysis for the selected project.

The backend handles Apache Ant and uploaded projects through their respective input directories.

For Apache Ant, it uses the prepared dataset directory and validates the version metadata.

For uploaded projects, it uses the generated AsTdEA input directory and validates its availability.

The analysis is executed through `EngineExecutionService`.

**Successful Response:**

Returns a response map containing:

- `status`
- `message`
- `projectId`
- `analysisOutput`

**Error Responses:**

| HTTP Status | Description |
|---|---|
| 400 Bad Request | Analysis input or file-related error |
| 500 Internal Server Error | Analysis execution interrupted or failed |

## 8. Project Processing Statuses

ArchiSense uses the following project statuses:

| Status | Description |
|---|---|
| `UPLOADED` | Project has been uploaded |
| `PROCESSING` | Project processing is in progress |
| `ANALYSIS_COMPLETED` | Project analysis completed successfully |
| `FAILED` | Project processing failed |
| `READY_FOR_ANALYSIS` | Project is available for analysis |

The upload workflow also tracks individual processing stages:

- `UPLOAD`
- `BUILD`
- `METADATA_PREPARATION`
- `ANALYSIS`
- `COMPLETED`

Failure information is persisted for registered projects to support later inspection.

## 9. API Integration

The React frontend communicates with the Spring Boot backend through HTTP requests.

The frontend API utility is located at:

```text
frontend/src/services/api.js
```

It provides functions for retrieving projects, versions, results, evolution data, and uploading projects.

Manual analysis is triggered through the analysis endpoint.

The frontend uses the returned information to populate the Overview, Projects, Analysis, Evolution, and Reports pages.

The Apache Ant evolution endpoint is specifically implemented for the `ant` project. Uploaded projects use their available single-version results rather than the Apache Ant inter-version endpoint.

## 10. Error Handling

The backend includes validation and error handling for project uploads, builds, metadata preparation, and analysis execution.

Examples include:

- Missing Maven project configuration.
- Invalid uploaded ZIP archives.
- Maven build failures.
- Missing Java source directories.
- Missing analysis metadata.
- Missing or unavailable analysis output.
- Interrupted analysis execution.

Upload processing failures are recorded with their corresponding stage and error message when a project has been registered.

GET endpoint error responses depend on the relevant controller and Spring Boot exception handling.
